- 重新核验入口可达性：`python scripts/check_links.py --only collections --write`
- 重新统计目录结构：`python scripts/check_links.py --only quark_shallow --write`
- 重新统计索引内嵌链接：`python scripts/check_links.py --only sheet_index --write`

## 这一份的口径和 [03b](03b-网盘资料清单.md) 不同

03b 那 11 条是**每个分享都翻完了整个目录树**，所以能给真实文件总数（爆笑初中9科 21943 个文件、1534 次请求、约 11 分钟）。

这一份的 44 条做不到。它们是教辅包，结构是「1 个总目录 → 几十个教辅子目录 → 每个子目录再按年级/版本分册」，全量遍历一条就要几分钟到十几分钟，44 条要好几小时。因此统一采用**浅层口径**：

| 口径 | 含义 |
| --- | --- |
| 只翻到第 2 层 | 顶层那个总目录不算，往下数第 2 层就是各科教辅名 |
| 报告「第 2 层 N 项」 | 这一包里收了几个教辅/几个教材版本 |
| **不报文件总数** | 第 2 层的文件数按层计，不是资料规模。深层才有 PDF，不翻 |

所以下面表格里的数字是**结构量，不是规模**。想知道某条到底多少文件、多大，自己加 `share_request_budget` 跑全量：

```bash
python scripts/check_links.py --only quark_tree
```

实测一条「初中电子课本」：第 2 层 20 个目录里只有 36 个文件，但第 3 层有 164 个目录——真正的 PDF 全在更下面。这就是为什么不能拿第 2 层文件数当规模。

## 失效与降级处理

第三方域名与平台处置都会让链接失效，按这个顺序排查：

1. **换官方域名**。把中转域名的路径接到 `pan.quark.cn` 上试试。
2. **跑探针**。`python scripts/check_links.py --only collections` 会区分「链接没了」和「网络问题」。
3. **分享页 200 不等于资料还在**。平台按违规下架时页面仍返回 200，只有 `quark_shallow` 分区的接口探测能看出来。
4. **提 issue**。标上条目 `id`，方便定位。
